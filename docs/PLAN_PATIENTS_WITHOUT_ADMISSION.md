# Ασθενείς χωρίς νοσηλεία — σχέδιο διόρθωσης δεδομένων (ΙΑΣΩ Θεσσαλίας)

Κατάσταση: **σχέδιο, δεν έχει εκτελεστεί τίποτα.** Κάθε αλλαγή σε δεδομένα παραγωγής θέλει ρητό ΟΚ του ιδιοκτήτη (CLAUDE.md).

## Τι βρέθηκε (28/10/2026, ερωτήματα μόνο ανάγνωσης)
- 2477 ασθενείς, 1286 αρχειοθετημένοι → 1191 στη λίστα.
- Από τους 1191, **479 δεν έχουν καμία γραμμή στο `patient_admissions`**:
  - ~467 δημιουργήθηκαν 22–23/10 από την εισαγωγή θετικών καλλιεργειών (PDF εργαστηρίου): έχουν τμήμα (`department_id`) και `status = 'active'` (ή `discharged` για 20), αλλά **ούτε `admission_date` ούτε νοσηλεία**. Οι 429 έχουν δείγματα.
  - 12 δημιουργήθηκαν 28/10 (συγχρονισμός FileMaker, `created_by` κενό): χωρίς τμήμα, με δείγματα.
- Επιπλέον: 520 ασθενείς έχουν νοσηλεία αλλά `patients.admission_date` κενό — η λίστα έδειχνε «—» στην ημερομηνία εισαγωγής (διορθώθηκε στην οθόνη, βλ. Βήμα 1).
- Το κανονικό UI (`Νέος ασθενής`) απαιτεί ημερομηνία εισαγωγής και ο trigger `patients_create_initial_admission` φτιάχνει τη νοσηλεία — άρα οι ασθενείς χωρίς νοσηλεία έρχονται **μόνο από εισαγωγές/συγχρονισμό**.

## Βήμα 1 (έγινε, κώδικας)
Η λίστα Ασθενών δείχνει «Χωρίς νοσηλεία» (δεν μετράει στους «Ενεργούς»), φίλτρο κατάστασης «Χωρίς νοσηλεία», ημερομηνία εισαγωγής από την τελευταία νοσηλεία. Το κουμπί του κενού μητρώου λέει «Νέος ασθενής».

## Βήμα 2 — συμπλήρωση νοσηλειών (θέλει ΟΚ)
Για ασθενείς **με δείγματα και χωρίς νοσηλεία**:
1. Πρώτα μόνο ανάγνωση: πόσοι είναι, με τμήμα και πρώτη ημερομηνία δείγματος (`min(collected_at, requested_at)` σε ώρα Αθήνας), πόσοι χωρίς τμήμα.
2. Δημιουργία γραμμής `patient_admissions`: `department_id` = του ασθενούς, `admission_date` = ημερομηνία πρώτου δείγματος, `status` = του ασθενούς, `admission_source = 'lab_import_backfill'` ώστε να βρίσκεται και να αναιρείται.
3. Ασθενείς χωρίς τμήμα (12 του συγχρονισμού): τμήμα από το δείγμα αν υπάρχει· αλλιώς μένουν «Χωρίς νοσηλεία».
4. Ασθενείς χωρίς δείγματα (49 + 1): δεν αγγίζονται — απόφαση ιδιοκτήτη (αρχειοθέτηση ή διαγραφή μένει σε εκείνον).
5. Εκτέλεση σε συναλλαγή με `begin; … rollback;` πρώτα για έλεγχο μετρήσεων, μετά με ΟΚ το πραγματικό `insert` (`create`, όχι `drop/delete`).
6. Αναίρεση: `delete … where admission_source = 'lab_import_backfill'` — **τρέχει ο ιδιοκτήτης στο SQL Editor** (οι `delete` δεν εκτελούνται από τον agent).

## Βήμα 3 — να μη ξαναγίνει
- Εισαγωγή PDF και συγχρονισμός FileMaker: όταν δημιουργούν ασθενή από δείγμα, να δημιουργούν και νοσηλεία (τμήμα + ημερομηνία δείγματος) ή να μην βάζουν `status = 'active'`.
- Βρες πού ζει ο κώδικας του συγχρονισμού (δεν υπάρχει στο repo: το `supabase/functions` δεν γράφει στον πίνακα `patients`· πιθανώς SQL function στη βάση).
- Τεστ που να αποτυγχάνει αν η εισαγωγή αφήνει ασθενή `active` χωρίς νοσηλεία.

2. Οι 50 ασθενείς χωρίς δείγματα: αρχειοθέτηση;
